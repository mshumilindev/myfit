# My Fit — особиста фітнес-платформа

Перший сервіс — трекер тренувань. Архітектура одразу закладена під наступні
сервіси (харчування, AI-оцінка тіла, програми тренувань): спільний акаунт,
кожен сервіс живе у своєму просторі API та своїй плитці в меню.

## Структура

```
gym-tracker/
├── server/     Node + Express + TypeScript + SQLite (better-sqlite3)
│   └── /api/auth/*      — платформенна авторизація (JWT, один акаунт)
│   └── /api/tracker/*   — сервіс №1: тренування
├── client/     React + Vite + TypeScript, PWA (offline-first)
├── desktop/    Electron-додаток у macOS-треї (запускає сервер + вікно)
└── cloudflare/ доступ з телефона через свій домен (SETUP.md)
```

## Швидкий старт (на Маку)

```bash
cd gym-tracker
npm install          # ставить залежності всіх трьох частин (workspaces)
npm run build        # збирає server + client + desktop
npm run tray         # іконка 🏋️ з'явиться в треї біля годинника
```

Один Node-сервер — три клієнти:

- телефон: PWA у браузері (додай на головний екран) — офлайн-режим і черга;
- трей: клік по іконці → швидке вікно біля годинника;
- десктоп: у меню трею «Відкрити десктопний додаток» → повноцінне вікно
  (або просто `http://localhost:4477` у браузері).

Перший запуск: створи акаунт (після цього реєстрація закривається).

### Режим розробки

```bash
npm run dev          # server на :4477 (tsx watch) + client на :5173 (vite HMR)
```

## Офлайн-синхронізація (як це працює)

- Телефон завжди пише зміни у локальну чергу (`localStorage`) і одразу
  оптимістично показує їх в UI.
- Коли сервер доступний: черга відправляється по порядку → черга чиститься →
  клієнт бере повний стан із сервера і повністю заміняє локальний кеш.
  Сервер — єдине джерело правди.
- Всі id генеруються на клієнті (UUID), а записи йдуть через upsert — тому
  повторна відправка черги безпечна (ідемпотентна).

## Зали та нагадування «забув залогувати»

- У трекері → «🏟 Мої зали» → додай зал, стоячи в ньому («📍 Я зараз тут»).
- Коли додаток відкритий і ти фізично в радіусі залу, він записує точку
  присутності (не частіше раз на 5 хв; точки теж працюють офлайн через чергу).
- Сервер збирає точки у «візити». Якщо візит тривав 1+ годину і жодне
  тренування не перетинається з ним — на головній трекера з'явиться картка:
  «Схоже, ти був у залі, але тренування не записане» з кнопками
  «Залогувати заднім числом» (створює тренування на час візиту) і
  «Це не тренування».
- Обмеження, чесно: браузер не дає геолокацію у фоні, тож точки з'являються
  лише в моменти, коли ти відкриваєш додаток. Відкрив у залі — візит
  зафіксовано. Push-нотифікацій поки немає — нагадування видно в додатку.

## Правила тренування

- «Почати тренування» → нове тренування; якщо якесь ще було відкрите,
  воно закривається автоматично і позначається ⚠️.
- Відкрите тренування «живе» максимум 8 годин — далі закривається само
  (час завершення = старт + 8 год) і позначається ⚠️ «можливо, записане
  не повністю». Правило працює і на сервері, і локально офлайн.
- Будь-яке тренування можна редагувати після завершення.

## Shell: як додати новий продукт

Платформа складається з shell'а (авторизація, синк, топбар, меню) і
сервіс-модулів. Щоб додати продукт (наприклад, «Харчування»):

1. **Сервер**: створи `server/src/<service>.ts` з роутером(ами) і додай запис
   у реєстр `server/src/services.ts` → API буде на `/api/<service>/...`
2. **Клієнт**: створи папку `client/src/services/<service>/` з кореневим
   компонентом (внутрішню навігацію сервіс веде сам) і додай запис у реєстр
   `client/src/shell/registry.ts` → плитка з'явиться в меню автоматично.
3. Авторизація, офлайн-черга, синк-статус і топбар уже дає shell.

- AI-оцінка тіла: окремий сервіс, що ходить в Ollama на цьому ж Маку або
  в Gemini API — фото нікуди не витікають, якщо Ollama.
