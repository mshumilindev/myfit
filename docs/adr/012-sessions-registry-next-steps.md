# ADR 012 — реєстр сесій і пристроїв: що додаємо до SPO-212 (SPO-437)

**Статус:** прийнято (04.11.2026), реалізація SPO-436 у цьому PR; рішення прийняті за best practices за дорученням власника.

## Контекст

Реєстр сесій уже є (SPO-212): `users/{uid}/sessions/{deviceId}`, лише через функції (`sessionCheck/List/Revoke/RevokeOthers/End`), клієнт — `SessionsSheet`. Відкликання одного пристрою — прапорець `revokedAt`, який цільовий пристрій бачить на старті й фокусі; «звідусіль, крім цього» відкликає всі refresh-токени (інші пристрої втрачають доступ щонайбільше за ~годину). Екран «Мої пристрої» (SPO-436) потребує: тип пристрою й зображення, місто/країну, push про новий вхід, швидшу реакцію на відкликання.

## Рішення

1. **Модель лишається.** Додаємо поля запису сесії: `kind` (`phone|tablet|laptop|desktop|watch`), `shell` (`pwa|browser|electron|android|ios`), `firstSeenAt`. Визначаються на сервері з User-Agent у `sessionCheck` (`sessionsPure.ts`); невідоме → `kind:'unknown'` з нейтральним зображенням. Нові поля відкриті (метадані пристрою, не користувацький вміст), як і наявний `label`.
2. **Місце входу:** лише слова «місто, країна»; сирий IP не зберігається й не передається назовні. Джерело — офлайн-база GeoIP усередині функції (DB-IP Lite City, CC BY 4.0, без реєстрації; альтернатива — MaxMind GeoLite2 з акаунтом і EULA). Пошук лише при створенні запису й при зміні країни; база вантажиться ліниво. Якщо бази немає або IP не знайдено — місце порожнє, UI показує лише тип і час. Спершу перевірити, що `placeFromHeaders` на `*.cloudfunctions.net` справді порожній (staging, лише читання). Атрибуція ліцензії — в «Мої дані»/політиці (`{{ЮРИСТ}}` узгодити текст).
3. **Миттєвість відкликання:** окремий мінімальний документ `users/{uid}/sessionState/{deviceId}` (лише `revokedAt`), який пристрій слухає; rules — читання лише власником, запис лише функціями. Перевірка на старті/фокусі лишається запасним шляхом (офлайн). Ціна: один слухач на пристрій.
4. **Vault і локальні дані при відкликанні:** без нових механізмів. `sessionCheck → false` запускає той самий вихід (`afterSignOut` + `wipeAfterSignOut`, `deviceWipe.ts`): чистить vault-ключ, запечатані сховища, кеші й Firestore-кеш. Дані на сервері не страждають; несинхронізовані локальні записи — як у штатному виході (прапорець, `waitForPendingWrites`).
5. **Push про новий вхід:** `kind:'login'` у наявній інфраструктурі `push.ts`, нового процесора немає. Текст нейтральний («Новий вхід у ваш акаунт»), без міста й пристрою на екрані блокування; деталі — на екрані. Чи потрібна окрема згода, окрім наявного дозволу на сповіщення, і зміни політики — `{{ЮРИСТ}}`.
6. **Зображення:** ліцензований набір (рішення власника), SVG/WebP, узагальнені пристрої без брендів, читаються в усіх темах. Конкретний набір і ліцензія обираються в задачі дизайну (SPO-438) після перевірки комерційної ліцензії для вбудовування в застосунок; запис у `docs/compliance/`. Якщо жоден набір не дає єдиного стилю — повернути питання власнику (а не змішувати стилі).
7. **Ролі:** лише власні сесії; у Coach Dashboard екрана немає (рішення власника).

## Уточнення після дизайну (04.11.2026)

- **Зображення — не фото, а контурні силуети** (`DeviceImage` у кіті, всередині `IconTile`). Безкоштовної бібліотеки зображень моделей із чистою ліцензією немає: `device-frames-media` без ліцензії; `react-device-frameset-recent-models` / `devices.css` (MIT) — старі моделі, peer-залежність React ≤18 (конфлікт із React 19), сирий hex/px CSS проти правил кіту. Підміна на рамки/фото — окрема задача, `DeviceImage` лишається єдиним місцем.
- **Вид пристрою:** `kind` = `phone | tablet | computer | unknown` (браузер не відрізняє ноутбук від настільного ПК). Точна модель («iPhone 18 Pro Max») є лише там, де її знає система (нативний застосунок); у браузері — браузер + ОС. Записи без `kind` клієнт вгадує з підпису, наступна перевірка їх доповнює.
- **Push про вхід:** ключ `signin`, текст без місця й пристрою; шле `sessionCheck`, коли з'являється новий пристрій і вже є інший живий (перший пристрій акаунта — не новина).
- **Миттєве відкликання:** `users/{uid}/sessionState/{deviceId}` = `{revokedAt}`, дзеркалиться при відкликанні, видаляється з записом сесії; get лише власник.
- **GeoIP (DB-IP Lite) НЕ реалізовано:** потребує рішення власника щодо ліцензії/атрибуції (CC BY 4.0) та розміру функції; місто/країна лишаються з edge-заголовків, якщо їх дає хост (перевірка на staging — відкрита). Блокер названо в плані.

## Розбиття розробки (після дизайну SPO-438)

1. Сервер: `kind/shell/firstSeenAt`, GeoIP, `sessionState`, rules + тест rules, push `login`, реєстр даних R7 + політика.
2. Клієнт: слухач `sessionState`, екран «Мої пристрої» на кіті, i18n 5 локалей.
3. Зображення: набір + ліцензія + сторі.
4. Тести: SPO-439.

## Наслідки й ризики

- GeoIP-база збільшує функцію (~десятки МБ) і потребує щомісячного оновлення (CI-задача або ручна); якщо це неприйнятно — місто прибираємо, лишаємо країну за заголовками, якщо вони будуть.
- Слухач додає читання Firestore на пристрій; ліміти — на одну людину, обмежені кількістю пристроїв.
- Юридичне (`{{ЮРИСТ}}`): строк зберігання записів сесій, атрибуція DB-IP, текст push, зміна політики й `policyVersion`.
