# ADR 001 — Storybook як каталог UI-кіту

- Статус: прийнято, 2026-09-28
- Зміна: dev-залежності `storybook@^10.6` і `@storybook/react-vite@^10.6` у `client/`.

## Контекст

Нові сторінки (Health, Log activity, Next up) наплодили власні копії одних і тих
самих шматків: два різні календарі, три перемикачі, кілька «сегментів», рядки
списків із захардкодженими hex. Внутрішня галерея `#/uikit` — один довгий екран
без станів, локалей і в'юпортів; перевіряти на ній примітив незручно.

## Рішення

Storybook 10 (`@storybook/react-vite`, React 19, Vite 6) у `client/.storybook`.
Кожен примітив `components/ui/` має `*.stories.tsx`; тест `kit.test.ts`
вимагає це. Правило — `.cursor/rules/ui-kit.mdc`, контракт — `docs/UI-KIT.md`.

## Ціна і що купуємо

- Тільки devDependencies: у PWA-бандл нічого не потрапляє (сторіз не
  імпортуються з `main.tsx`; `vite build` їх не бачить).
- +108 пакетів у lock-файлі (усі dev; 2 патч-апдейти транзитивних:
  `@testing-library/user-event` 14.6.1→14.6.7, `@jridgewell/sourcemap-codec`);
  `npm run build-storybook` ~20 с.
- Купуємо: ізольований перегляд кожного стану на 390/1280 і в 5 локалях,
  скріншот-порівняння до/після, одне місце, де видно, що кіт уже вміє —
  менше дублікатів у сторінках.

## Альтернативи

- Лишити тільки `#/uikit`: без станів/локалей/в'юпортів, росте в один екран.
- Ladle: легший, але менше екосистеми (в'юпорти, тулбари) і гірша підтримка React 19.
