# Додати тему за ~10 хвилин (SPO-344, ADR 010)

Тема = один файл `client/src/themes/<id>.css` із токенами контракту (`client/src/themes/contract.ts`) на `html[data-theme='<id>']`. Весь UI читає лише токени, тож більше нічого міняти не треба.

1. `npm run theme:new <id> "<Назва>"` — створює файл (стартові значення з Brass Glass) і додає тему в `themes/registry.ts`.
2. Відредагуйте значення: ідентичність (`--font*`, `--color-text*`, рамп акценту `--color-accent-*` і `--color-on-accent`, нейтралі, родини gym/note), стиль головної кнопки (`--btn-*`), скло (`--glass-accent-k`, бази й краї), таббар і кнопку Start (`--tabbar-*`, `--fab-*`), поверхні (`--color-bg`, `--color-surface`, `--glass-*`), настрої (`--mood-*`), радіуси (`--radius-*`), типографіку (`--type-*`), лаву (`--lava-*`), пластини (`--plate-*`).
   Скіни застосунків — блоки `html[data-theme='<id>'].theme-<apex|learn|roster|nutrition|coach>` у тому ж файлі: обов'язково `--lava-2`, `--lava-3`; за потреби `--lava-1`, `--glass-raised-base`, `--plate-*`, `--t-*` (контракт: `THEME_SKINS` у `contract.ts`, guard перевіряє всі п'ять).
   Світлий режим цієї теми — блок `html[data-theme='<id>'][data-mode='light'] { …токени контракту… }` (і значення `light` у `AXES.mode` у `registry.ts`).
3. `npx vitest run tests/theme-contract.guard.test.ts tests/contrast-matrix.guard.test.ts` — контракт (усі токени, нічого зайвого) і AA-контраст для теми × день/ніч × 6 скінів. Червоне = виправляти токени, не тест.
4. Storybook: перемикач **Theme** у тулбарі; піксельна галерея всіх історій: `npm run audit:pixels -- --dir shots-<id> --theme <id>`; рефакторинг, що має бути невидимим: еталон до змін (`--dir shots-ref`), після — `--dir shots-new --ref shots-ref` (код виходу 1 і список історій, якщо хоч один піксель змінився).
5. Перемикач для користувача з'являється в Налаштуваннях автоматично, коли тем більше однієї.

Палітра за замовчуванням (текст, акцент, статуси) лежить у `styles.css`; тема може її перевизначати, але скіни (`.theme-apex` тощо) ставлять акцент власним класом — перевіряйте контраст-матрицею.

Перший кадр: якщо збережена тема відрізняється від дефолтної, до виконання JS видно дефолтну (інлайн-скрипт у `index.html` прибитий хешем у CSP — якщо це стане проблемою, додати рядок у нього й оновити хеш у `firebase.json`).

## Осі вигляду: режим, акцент, щільність

`AXES` у `themes/registry.ts` — незалежні від теми атрибути на `<html>`: `data-mode`, `data-accent`, `data-density` (зараз у кожної лише значення за замовчуванням, тож вигляд не змінюється). Нове значення = запис у `AXES` + блок у `themes/_axes.css` (`html[data-theme][data-density='compact'] { … }`, `[data-theme]` потрібен, щоб перебити блок теми незалежно від порядку). Guard вимагає CSS-блок для кожного не-дефолтного значення. Автоматичне нічне приглушення (`data-sleep='night'`) — окремий стан часу виконання, не вісь.

## Кіт читає токени, а не id теми (етап 2)

Структурні правила кіту (`glass.css` та сусідні файли) стоять на `html[data-theme]`, без id конкретної теми: нова тема отримує їх одразу, а відрізняється лише токенами. Скіни застосунків (`:root.theme-apex` тощо) мають специфічність (0,2,0), тож вищі за акцент теми (0,1,1) і далі перефарбовують акцент усередині Apex / Learn / Roster / Nutrition / Coach. Брасове скло: `--glass-accent-k: 1` (скло й hero забарвлені акцентом); тема без забарвлення ставить `0` і дає власні бази та краї (`--glass-base-*`, `--glass-edge`).
