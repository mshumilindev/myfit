# Unwell 2.0 — види хвороб і план повернення

Статус: план, код ще не писався. Мова: документи укр., код англ.

## 1. Проблема

Зараз «unwell» — це один плоский стан: `RestPeriod{mode:'illness'}` без причини і без ваги.
Все, що з нього випливає, однакове для 1 дня застуди і 3 тижнів ковіду:

- `store.illnessReturn()` — картка «повертайся м'яко» лише якщо було ≥2 дні, показується 2 дні після кінця й гасне після першого ж тренування;
- `rpe.ts` — плоский мінус 6% до e1RM, що згасає за 7 днів;
- `restTimer.ts` — плоскі +20 с на відпочинок, якщо хвороба була <7 днів тому;
- `SessionView.rpeCtxFor` — власний обхід періодів (дублює логіку);
- Atlas (`actions.ts` → `case 'illness'`) сам створює період із `note:'Atlas'`;
- Injury має ще одну «illness» гілку (`RehabReason 'illness'`, `GENERAL_REASONS`) — друга, паралельна система для того самого.

Немає: типу хвороби, ваги (температура / «вище чи нижче шиї»), плану повернення, який залежить від тривалості, обліку по типах.

## 2. Принципи (щоб не було клаттеру)

1. **Одне джерело правди:** один чистий модуль `client/src/illness.ts` з функцією `illnessState(periods, workouts, now)`. Усі споживачі (RPE, rest timer, банер Today, Session coach, Auto builder, календар, Atlas) читають лише її. Жодних обходів `restPeriods` у компонентах.
2. **Жодного нового екрана, табу чи kit-примітива.** Все на існуючих: Health-форма, `Banner`, `Card`, `PresetChips`, `Segmented`, `Tag tone="illness"`, `IconTile`, `Sheet tone`, `StatStrip`.
3. **Одна сім'я кольору (`illness`, бурштин).** Тип відрізняється іконкою і підписом, а не новими кольорами.
4. **Один слот банера на Today:** новий банер замінює і «ongoing sick», і `illnessReturn`; не додаємо третій.
5. **Не блокуємо і не лякаємо:** тренування під час хвороби/повернення можна почати завжди — лише м'яке попередження і обмеження підказок.
6. **Не медична порада:** поради — консервативні орієнтири; при тривожних симптомах — «до лікаря». Пороги — таблиця в одному місці, легко правити.
7. **Дані користувача не мігрувати руйнівно:** старі періоди без типу = `other`, поведінка як сьогодні.

## 3. Модель даних

Додаткове опційне поле на `RestPeriod` (Firestore-піддокумент `restPeriods` — поле адитивне):

```ts
export type IllnessKind =
  | 'cold' // застуда / ГРВІ
  | 'virus' // грип, COVID та інші віруси (окремо covid не виділяємо)
  | 'stomach' // шлунковий вірус / отруєння
  | 'mental' // ментальний стан: депресія, вигорання, тривога
  | 'other'; // інше / не знаю (за замовчуванням для старих записів)

export interface IllnessInfo {
  kind: IllnessKind;
  // Симптоми (вище/нижче шиї) і температуру користувач НЕ вводить: вони виводяться
  // з типу і тривалості (cold → вище шиї, virus/stomach → системно; довше = важче).
}
// RestPeriod.illness?: IllnessInfo
```

Похідні (не зберігаємо): `daysOut`, `symptomFreeDays`, фаза плану, дні повернення.

### Тривалість і тип → план повернення (таблиця в `illness.ts`)

Базові орієнтири, параметризовані (`RETURN_TABLE`), не вбиті в логіку:

| Тип                            | Мінімум відпочинку                                                | Повернення (після одужання)                                                                                                                             |
| ------------------------------ | ----------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| cold, neck-up, без температури | можна легко (за «neck check»), інакше 1–2 дні                     | 1 легка сесія (~80%), далі нормально                                                                                                                    |
| cold, systemic / flu           | до 24–48 год без температури                                      | 2–4 дні розгону залежно від `daysOut`                                                                                                                   |
| covid                          | не менше 5–7 днів від початку симптомів + 24–48 год без симптомів | градуйоване повернення ≥ 7 днів (ходьба/легко → ~50% → ~70% → ~85% → норма), кап пульсу/RPE, стоп-симптоми (біль у грудях, серцебиття, задишка → лікар) |
| stomach                        | доки не їсться/п'ється нормально                                  | 1–2 дні: регідратація, без важких днів                                                                                                                  |
| other                          | як `cold` systemic                                                | як `flu`                                                                                                                                                |

Масштаб за `daysOut` (усередині кожного типу): 1 день — без ритуалу; 2–3 — 2 сесії розгону; 4–7 — 3–4; 8–14 — 5–7; >14 — «повернення після перерви» (детренінг) на кілька тижнів, з нагадуванням про лікаря при затяжних симптомах (>4 тижні — підказка про ускладнення, особливо covid).

Фази: `sick` (лікуємось) → `returning` (день N з M; множники `volume`, `intensity`, `restAddSec`) → `clear`. Перехід `returning → clear` за кількістю відпрацьованих сесій (як `ADVANCE_STREAK` в `injury.ts`), а не за календарем; користувач може завершити раніше.

## 3a. Що вже є і має зберегтись (інвентар поточного Unwell)

- Health-форма: тип, ім'я, «How long» (Just today / Until I'm better / From an earlier day + Since when), «No end date» підказка, «Still ongoing», неможливо планувати наперед, логування минулого; обробка перетину з залогованими тренуваннями («skips N days», «count as sick day», Replace/Merge); «Still healing → продовжити в rehab-план».
- Today: програмна картка в режимі illness («Taking care», «Resting up · day N», пілюлі «Streak protected» / «Program paused»), кнопка «I'm recovered» → діалог «Come back from illness?» («Yes, I'm recovered» / «Still unwell»), картка «Welcome back».
- Тиждень: піл `sick`; календар/шторка дня; історія й таймлайн Health з фільтром Unwell; Atlas.
- Дизайни (полотно Unwell 2.0) вбудовують усе це, а нове — тип, план повернення, попередження на старті, редагування залогованого, Mental — додається без нових екранів-дублікатів.

## 4. Один модуль — усі наслідки

`illnessState()` повертає `{ phase, kind, daysOut, returnStep, returnSteps, caps: { volume, intensity, rpeCut, restAddSec }, needsDoctor }`.

Споживачі (замість власної логіки):

- `rpe.ts` — `illnessDaysAgo` замінюється на `rpeCut` зі стану (тип і тривалість, а не плоскі 6%→0).
- `restTimer.ts` — `illness: boolean` → `restAddSec` зі стану.
- `SessionView.rpeCtxFor` — прибрати ручний цикл по `restPeriods`, брати `illnessState`.
- `SessionStartCoach` — рядок «Повернення після {тип}: день N з M — ~70% об'єму» (існуючий `Tag tone="illness"`).
- Auto builder / підказки навантаження — застосовують `caps.volume/intensity`.
- `store.illnessReturn()` — видалити, замінити на `illnessState`.
- Atlas — `actions.ts` створює період через ту саму фабрику з `kind`; `activeIllness()` читає `illnessState`; відповіді залежать від типу і фази.

## 5. Entry points (де користувач це бачить і запускає)

Жодного нового входу — лише збагачуємо існуючі:

1. **Health-сторінка → форма Illness** (єдине місце створення): додати рядок `PresetChips` «Що саме» (Застуда · Грип · COVID · Шлунковий · Інше) і `Segmented` «Симптоми» (вище шиї / нижче шиї) + перемикач «Була температура». Поля опційні, за замовчуванням `other`.
2. **Start sheet → плитка Здоров'я** (існує) — без змін, веде в ту саму форму.
3. **Календар / шторка дня** (`DayHistorySheet`): нотатка хвороби показує тип (іконка + назва) і «день N»; шторка вже кольорова через `Sheet tone`.
4. **Today:** один банер (слот `illReturn`):
   - `sick`: «Хвороба · {тип} · день N», кнопки «Краще / Так само / Гірше» (check-in) і «Я одужав» (закриває період і запускає `returning`);
   - `returning`: «Повернення: день N з M · ~70% навантаження» + «Почати легку сесію» (існуюча кнопка `restStartLight`).
5. **Atlas:** «я захворів на ковід» → створює період з `kind`; «як мені повернутись» → відповідь із `illnessState`.
6. **Початок сесії під час `sick`:** не блокуємо; одна м'яка підказка в Session coach.

## 6. Облік окремо (статистика)

- `today/calendarData.ts` / `widgets/calendar.tsx`: `sickN` лишається (загальний), додаємо розбивку по типах у підписі.
- Health history: фільтр `illness` розкладається чипами за типом (без нових кольорів).
- Trends/Health: «Днів хвороби за період» по типах; «середня тривалість» і «повернення до норми» (через скільки сесій).
- Серія (streak) і пауза програми — як зараз (дні хвороби не «пропущені»).

- Видалити `illnessReturn`, плоскі константи в `rpe.ts`/`restTimer.ts`, дублікат у `SessionView`.

## 9. Рішення (30.09) і звірка з рекомендаціями

Рішення: типи cold / virus / stomach / mental / other; лише кнопка «Я одужав» (без щоденних check-in — з моделі прибрати `checkins`); Injury-«illness» лишається окремо (розділ 7 про його видалення — скасовано); попередження на старті сесії — так; редагування вже залогованих періодів в історії — обов'язково (окремий екран, зараз його немає).

Mental: без «neck check»/температури; жодного «відпочивай»-тиску; логіка «за самопочуттям», легкі сесії/прогулянка зараховуються, план гнучкий, підказка звернутись до близьких/фахівця.

Звірка (пороги в `RETURN_TABLE`, легко правляться):

- Температура > 38 °C — не тренуватись, повертатись лише повністю без температури; «neck check»: лише симптоми вище шиї — можна легко, нижче шиї (кашель у грудях, ломота, ШКТ) — ні; лише біль у горлі — пропустити день і перевірити наступного ([Return to Play After Infectious Disease](https://pmc.ncbi.nlm.nih.gov/articles/PMC7123245/)).
- Шлунковий: повертатись, коли симптомів немає; практично — 48 год після останньої діареї/блювання (те саме джерело).
- Вірус/COVID-подібні: ≥72 год без симптомів перед легким навантаженням, далі ~1 тиждень легкого (~3 MET) і ~50% звичного об'єму/інтенсивності, прогрес за самопочуттям; червоні прапорці — температура, задишка, кашель, тахікардія, сильна втома → зупинитись і до лікаря ([Safe Return to Exercise after COVID-19](https://pmc.ncbi.nlm.nih.gov/articles/PMC8407897/)).
- Тривалість розгону залежить від тривалості й тяжкості хвороби (те саме джерело №1) — тому масштаб за `daysOut`.

Це загальні орієнтири, не медична порада; в UI — підказка «якщо симптоми тривають/погіршуються — лікар».
