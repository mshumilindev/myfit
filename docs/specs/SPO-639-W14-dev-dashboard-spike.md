## 2. Рекомендація

**A (рекомендовано): збирач + dev-сервер Vite + lazy-екран лише в DEV.**

1. **Збирач** `scripts/dev-dashboard/collect.mjs` (чиста логіка в `scripts/lib/`, тести) пише знімки `.claude/state/dash/<гілка>.json` (gitignored): git (коміти, ahead/behind, вік), `wf` (пункти, докази, час подій), результати прогонів (vitest `--reporter=json`, lint, typecheck, `coverage:guard`, bundle/lighthouse, з тривалістю), CI з GitHub REST по `head_branch` (час job, червоні, перші падіння), AC з Linear (опційно, ключ лише з env). Запускається автоматично: git-хуки `post-commit`/`post-checkout` (≤ 1 с, лише git+wf), `wf`-події, обгортка прогонів `scripts/dev-dashboard/run.mjs <команда>` (міряє час і зберігає результат), нічний/ручний збір CI.
2. **Сервер:** Vite-плагін `configureServer` (існує лише в `serve`, у `build` його немає) віддає `/__dev/dashboard/*` з тих знімків. Перевірки на сервері: `req.socket.remoteAddress` loopback, `Host` = localhost/127.0.0.1/[::1] (захист від DNS rebinding), лише GET, без CORS.
3. **Клієнт:** вкладка «Dev» в admin, **лише якщо `import.meta.env.DEV` і hostname = loopback** (дві незалежні умови); код екрана вантажиться `import()` усередині `if (import.meta.env.DEV)`, тож у прод-бандл не потрапляє (перевіряє тест на `dist`: немає рядків модуля, немає `/__dev/`). Таб на гілку; кожна гілка = знімок.
4. **Дані не в Firestore**, не в `dataRegistry`, не шифруються (це метадані розробки на диску розробника, не дані користувачів).

Альтернативи: **B** окрема статична HTML-сторінка з тих самих знімків (простіше, але поза Spotter — суперечить запиту); **C** Firestore-колекція для дашборда (ламає «лише localhost», нова категорія даних, rules, реєстр, юридичне: відхилено).

Ціна A: +1 dev-залежність нема (Node API), бандл прод 0 байт, ререндер лише в DEV; ризик — dev-сервер доступний у LAN при `--host`.

## 5. Ризики для risk assessment (W16, High позначено)
