Pass 3 — taken from styles.css (the staged CSS), overriding my earlier guesses

  cards and the footnote only. The preview aside is `display:none` at EVERY width (it's never shown) → not drawn anywhere now (previous
  P16-Preview-States board removed). Desktop (>= 960 px): the client grid hides every client card (`:not(.trainer-self-card)`) → self card + week table.
- Hierarchy: loud = the live client card (`.tr-client-card.live`: 104 px band, pill "Training now · clock", accent ring + bottom line → `card(tone='hero')`),
  TrainerLivePanel in a trainer's client profile (hero), the ClientPage "Last time on this day" card (hero, t-d1 name) with the green live banner above it,
  the TrainerLiveBanner big card. Rosters = compact 52-px-avatar rows; dormant only turns the sub-line danger (no red card). Admin list = dense quiet rows.
- Admin phone (< 720 px): no table head; row = who (34 avatar, name, @user, re-request line) · role tag · ⋯, then the status line indented 45 px;
  trainer / last session / volume columns hidden. Me card = who · role · status. Desktop: full 7-column grid, me card aligned to it.
- Status colours exactly as the code: strip live = green ring + green dot, fresh (< 2 d) = accent ring, quiet = grey ring, dormant = danger ring + red
  warning badge; admin status live = accent + pulsing accent dot, Active = green dot, muted/danger = grey dot (danger text red); trainer table
  Now/ok = green, dormant/danger = red; profile "Training now" pill = accent; tr-live-card = accent ring; TrainerLiveBanner live = accent,
  offline = danger, finished = ok; ClientPage live = ok.
- ProfileView: `.profile-detail-fields` are always rendered for self and admin (no CSS hides them — the Edit button only toggles an
  unstyled class); Security is hidden unless the password is being edited, and while it is, the Settings title, language and rows hide.
  Settings = flat divider rows, Sign out in danger. Atlas row uses the robot icon (not a face).
- Real imagery: Atlas = public/atlas/atlas-3.webp portrait (strip lead + solo row). No exercise photos or body maps exist in any P16 component
  (ClientPage, TraineeSessionView, TrainerLivePanel, HistoryTimeline rows, TrainerLiveBanner are text/number only) → none drawn.
  Gym thumbnail in profile = GymThumb (runtime photo → OSM → house graphic) → kit house graphic.

Key source facts

- People sub-app = `views/RosterApp.tsx`. Label and nav by role (`peopleLabelFor` / RosterApp `appLabel`): trainer **Clients · Me · Apps**, admin **Users · Me · Apps**, member **Me · Apps**.
  Header: spotter · <label> (app switcher) · bell (unread badge, opens the Milestones feed tab) · language. No Mastery badge in this header.
- Tabs: `clients` → TrainerView, `users` → AdminView, `me` → ProfileView(userId="me", embedded), `feed` → NotificationsView(embedded, title "Milestones").
  Tapping a person → ProfileView(userId, not embedded → back button), nav stays.
- Gym app role branches (TodayView): trainer's Today = only `TrainerClientsStrip` (Atlas lead / Atlas solo when no clients); admin's Today = member Today where
  the Atlas & clients core block is `TrainerClientsStrip`. Strip → ClientPage (overlay) → TraineeSessionView (overlay).
- Programs (Overview drill-in): `isCoach` adds the per-tile members button (AvatarStack or "Assign") → AssigneesSheet; ProgramBuilder menu adds "Assign to members".
- `TrainerLiveBanner` and `ProgramAssignDialog` exist in code but are **not imported anywhere** — drawn on row-3 boards labelled "not mounted".
- TrainerClientsStrip `view="list"` is supported by the component but TodayView never passes it (always stories) — drawn on the strip spec board, labelled.
- Night: `App.tsx` sets `data-sleep=night` on the root for the whole app, but `SpotterSky` and `SleepHero` are mounted only in the Gym-app return;
  the RosterApp branch returns earlier. So People screens at night flip palette only; the Gym Today (trainer) gets the SleepHero band.

- approximated: audit rows' resource text (`profile`) and the action-error message are mock values (server-provided).
