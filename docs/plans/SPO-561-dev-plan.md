# SPO-561: Start Drawer на мобільному завжди вміщується (план розробки)

Дизайн: SPO-562 (канвас «Start Drawer: малі екрани», затверджено власником 23.11.2026 з умовою нижче). Тести: SPO-563.

## Рішення власника (23.11.2026)

1. Поточний повний вигляд лишається дефолтом. Айтеми не зменшуємо без потреби.
2. Кількість плиток динамічна (аддони, замки, illness Notice, довгі локалі, системний шрифт). Тому **щільність обчислюється з вимірювання контенту, а не з `max-height`-щаблів** прототипу.

## Підхід

Хук `useDensityFit` (ядро, `client/src/components/startDensity.ts`), аналог Rail overflow (`useRailOverflow`: ResizeObserver, без брейкпоінтів):

- Рівень 0 = сьогоднішній вигляд. `data-density="0|1|2|3"` на `.start-sheet`.
- `useLayoutEffect`: вимірюємо, чи вміщується контент (`scrollHeight <= clientHeight` у скролері дровера). Не вміщається → рівень +1, повторюємо в тому ж layout-проході (до першого малювання, без миготіння). Вміщається → лишаємо.
- Перерахунок з рівня 0 при зміні: розмір вікна/`visualViewport`, склад контенту (підпис: кількість плиток, герой, Notice, локаль), масштаб шрифту. Так при зростанні місця вигляд повертається до повного.
- Рівні 1–3 лише CSS за `[data-density]` (feature-клас, не оверрайд кіту): прибрати підписи плиток → щільніші плитки і герой без sub → плитки в рядок, без заголовка. Значення з прототипу SPO-562, лише токени.
- Страховка: якщо й рівень 3 не вміщається, лишається внутрішній скрол (як сьогодні), `×` не перекриває (нижній відступ залежить від висоти `×`).
- Десктоп (`inline`, `.start-inline`): хук вимкнений, поведінка не змінюється.
- Нових залежностей, даних, рядків i18n, колекцій немає. Kit не змінюється (Sheet, TabBar, IconTile, Card як є).

## План регресії

Базова лінія (до змін, зелена): `StartSheet.*.test.tsx`, `TabBarStartLayer.test.tsx`, `tests/kit-guard.test.ts`, `exclusion.contract.test.ts`, `start-fab-audit.mjs`, `audit:stories` по StartSheet-сторі, `lint/format/typecheck`.

Не має змінитись: вигляд на 390×844+ з типовим набором (скрін до/після піксель-в-піксель), десктопний `.start-inline`, поведінка `×`, жести Sheet, порядок і доступність плиток.

Нові тести: unit `startDensity` (рівні, перерахунок, тригери, `enabled=false`, дедуп), компонентний (`data-density` за висотою контейнера), геометрія SPO-563 (нуль вертикального overflow, перекриття, обрізання; 320–412 × 568–915 × теми × локалі × набори аддонів).

Браузер: скріни кожного AC на localhost власника.

## Порядок робіт (одиниці однакової ваги)

1. Базова лінія: прогнати зелені тести/аудити (до змін).
2. `startDensity.ts` + unit-тести.
3. Підключення в `StartSheet`/`StartFrame` (`enabled = !inline`) + компонентні тести.
4. CSS рівнів 1–3 (токени з прототипу SPO-562, перевірити `--s-6/--s-10/--sz-44`).
5. Нижній відступ під `×`.
6. Story-набори для аудиту (мало/багато плиток, замки, Notice).
7. SPO-563: аудит геометрії Start Drawer + підключення в CI окремим шардом.
8. Скріни на localhost, до/після, 5 локалей, 4 теми.
9. Risk close-out: повторний `rg`-інвентар, реєстр закрито доказами, базова лінія зелена, швидкість.
10. Linear: AC з доказами, коміт локально (push/deploy лише за `cpd`).

Пакет змін торкається апки Gym лише в Start Drawer; нових апок/аддонів/тем немає, тож блок «превʼю-канвас» для `cpd` не діє.
