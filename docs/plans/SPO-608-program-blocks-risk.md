# SPO-608 · Блоки часу на рівні програми: оцінка ризиків і план (27.11.2026)

Причина: затверджені дизайни (M2: редактор дня, Today, Start-дровер, пікер у режимі блоку) містять блок у програмі.
Попередній план помилково виніс це зі скоупу (див. коментар у Linear). Це оцінка ДО коду (`risk-assessment.md`).

## Рішення про дані
`Program.blocks?: ProgramBlock[]` (`{id, day, position, spec, members}`) поруч з `items`, а не новий `kind` у `ExerciseKind`.
Причина: `ExerciseKind` спільний із сесійними вправами; `kind: 'block'` непомітно потрапив би в усі фільтри `kind === 'strength'`,
обсяг, Today, `startProgramDaySession`. Окреме поле нічого з цього не чіпає: споживачі, що його не знають, його ігнорують.
Блоки однакові щотижня (як `activities`), у циклічні тижні (`WeekPlan`) не входять. Зберігаються відкрито, як `items`
(каталожні назви + числа, жодного вільного тексту), тому шифрування й rules не змінюються (`firestore.rules` про `items` нічого не знає).

## Реєстр ризиків
1. Тиха втрата `blocks` при save/copy/diff (H×H) → round-trip тести кожного перебудовувача.
2. Тренерський шлях ігнорує блоки (M×H) → Фаза 2 винесена власнику; до неї тренерський редактор їх зберігає (passthrough), але не показує.
3. Блок у програмі впливає на формули (L×H) → не входить у `items`; `blocksMaths` + тест Today.
4. Порядок блоку в сесії (M×M) → позиція `n-0.5` від кількості вправ дня до блоку.
5. Розмір документа програми (L×M) → ліміт 7 блоків/день, 4 учасники на блок у `sanitizeBlocks`.

## Фази
- **I1 дані:** тип, `sanitizeBlocks`, normalize/saved, ops copy/clear, diff, `startProgramDaySession`; тести.
- **I2 UI власної програми:** картка блоку серед вправ дня (selfEditor/ProgramPage), Today-план, плитка Start.
- **I3 пікер:** «New time block», режим блоку з каталогом придатних вправ.
- **I4:** рядок Conditioning у Volume, темна тема, перезйомка превʼю SPO-556.
- **Фаза 2 (питання власнику):** тренерське призначення блоків (planCodec/ProgramLayer/версії).

## Доповнення за ревʼю й ходом розробки (27.11)
- Правила: `blockV` + `keepsBlocks` (як `cycleV`/`keepsCycle`): старий клієнт без `blocks` не стирає блоки. Тести J30–J33 написані, але не виконані в хмарі (немає емулятора): прогнати на пристрої власника (`npm run test:rules`).
- `afterItemId` посилається на рядок програми: при copyDay/clearDay/toMusclesMode блоки копіюються з перемапленим id або відкидаються (`model/dayBlocks.ts`).
- `cycleOps.mergeWeek` зберігає `blocks`; snapshot у `ProgramPage` включає блоки; `planCodec.runnableProgram` пропускає `blockV`.
- Імена власних вправ у блоці зберігаються відкритим текстом так само, як імена вправ (`items`): свідоме рішення, зафіксоване тут.
- Ролі: admin-trainer як trainer; каталожні програми лише для читання; CSV-експорт програми блоки не включає (рішення: поза скоупом, дані в загальному експорті/JSON).
- Фаза 2 (тренерські блоки) не робиться без рішення власника.
