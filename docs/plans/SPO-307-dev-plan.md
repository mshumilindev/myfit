# SPO-307 «Train like a pro»: Risk assessment і детальний план розробки

Статус: дизайн затверджено власником 25.11.2026 (канвас «Train like a pro: каталог програм», версія 10). Порядок: спайк → дизайн → **risk assessment** → план → розробка (`work-order.md`). Код не починається, доки `risk-reviewer` не перевірив High-ризики нижче.

## 0. Рішення власника, на яких стоїть план

1. Окремий аддон `train-like-a-pro` (id = ім'я файла іконки `store-icons/train-like-a-pro.webp`), потрібен лише Gym, доступний і новачкам. Advanced training лишається як є.
2. Нічого не копіюється й не редагується: одна дія «Start this program», програма йде як описана.
3. Одна активна програма одночасно. **Програму тренера перезаписати не можна.** Власну активну заміняє підтвердження (`ConfirmDialog`, історія лишається).
4. Програми, яким потрібен інший аддон (цикли тижнів, суперсети), видно, але заблоковано: мітка «Needs …», у деталях пояснення й «Get …».
5. Без фото людей і слотів під зображення (обкладинки: SPO-628). Ім'я атлета першим, кольором акценту.
6. На Programs, коли аддон не встановлено, тихий рядок входу в стор із «Get» (виняток із правила «без підказок встановити», бо Programs не розрахунковий екран).
7. Тренер у v1 не користується каталогом (спайк, розд. 10.2); Plus немає, усе безкоштовно.
8. Іконка (Blender): медаль зі штангою на графітовій плитці; анімована лише на сторінці аддона.

### 1.2 Чекліст категорій

- **Дані:** зачеплено (один новий тип документа в наявній колекції, поле `source`). Міграцій немає, старі програми без `source` працюють. Шифрування: вміст каталогу публічний; документ користувача йде наявним шляхом, активності запечатані. Експорт і каскад покриті наявним `programs/*` автора (тест).
- **Формули й моделі (інв. 8):** не зачеплено. `weeklyMuscleSets`/`classifyZone`/`acuteFatigueScore` лише читаються регресійним тестом каталогу; нових гілок логіки немає.
- **Ролі й права:** зачеплено. member створює/стартує; trainer у v1 каталогу не бачить (аддон `roles: member`); admin керує вмістом через репо; перезапис призначення тренера забороняється на сервері.
- **Аддони:** зачеплено, див. 1.3.
- **Офлайн, ідемпотентність:** старт іде через `setProgramStatus` (callable), тож потребує мережі, як і наявна активація власних програм; документ пишеться з клієнтським детермінованим id. Каталог доступний офлайн (чанк у кеші PWA).
- **UI:** екрани з дизайну (M1–M15, D1–D15), теми (світла, темна, нічна, акценти), 390 і 1280, 5 локалей, довгі рядки, a11y (фокус, клавіатура, disabled з поясненням).
- **Продуктивність:** фільтри лише над 48 записами; lazy-чанк; без нових запитів до Firestore, окрім одного `get/set` при старті.
- **Юридичне:** нових категорій, одержувачів, процесорів, згод немає (`legal-compliance.md` п. 1–13: нічого не змінює політику). Контент: імена атлетів як фактична атрибуція джерела, без фото й цитат, дисклеймер у деталях, takedown-контакт. Юридична вичитка відкладена власником (SPO-258), `{{ЮРИСТ}}` лишається. Запис у `categoryRegistry.ts` не потрібен (категорії з згодою немає).
- **Збірки:** PWA, Storybook, e2e зачеплені; Electron ні.

### 1.5 План регресії

- **Базова лінія (до змін, зелена):** `cd client && npx vitest run src/views/programs src/views/ProgramsView.cases.test.tsx src/data/programMine*.test.ts src/addons src/addonStore src/today src/coach/data/firestore/programPort*.test.ts`, функції `programs`, `npm run test:rules`, `tests/kit-guard.test.ts`, `npm run i18n:check`, `typecheck`, `lint`. Результат фіксується в Linear перед першим комітом коду.
- **Не змінюється:** `Program` без `source` поводиться як раніше; формули; Coach-шлях `prg-*`; AC-PROG-05 (одна активна власна); `keepsCycle`.
- **Нові тести:** по кожному H/M ризику (R1–R8, R10).
- **Ручна/браузерна перевірка:** чистий профіль (порожній `spotter.addons`) → Programs показує лише рядок «Get»; встановити → каталог; старт; видалити → програма на місці; профіль із тренерським призначенням → старт заблоковано. Скрін на `localhost:5173` кожного кроку.

### 1.6 Рішення людини й рев'ю

- Узгоджено: R1 (заборона перезапису тренерської; власник 25.11).
- До коду перевіряє `risk-reviewer`: R1, R2, R3 (rules, права, перенесення даних), інакше High не закриваємо.
- Питання власнику перед розробкою: немає відкритих. Припущення, які власник може змінити: trainer без каталогу (v1), старт потребує мережі.

## 8. Рішення (26.11, власник делегував вибір)

- **R25 — `assignProgram` не міняємо.** Поточна програма мембера визначається записом `assignments/{uid}` (його читає `programMine`), тож власна `active`-програма, що лишилась, не стає другою «поточною»; а старт із каталогу вже архівує інші власні `active` у транзакції. Правка `assignProgram` зачепила б тренерський потік поза скоупом SPO-307 (мінімальний дифф). Прогалину задокументовано; окремий дефект за потреби.
- **R24 — читання `assignments` не звужуємо.** Це загальна політика доступу тренерів, а не частина фічі; `programId` каталожної програми не містить персональних даних (id запису каталогу). Звуження — окреме рішення разом із рев'ю `coach-and-roles`.
- **Анімована іконка** — не блокує випуск: статична іконка 320×320 є й проходить контракт; анімацію додаємо окремою задачею, коли `gen.py` запущено на Маку.
- **e2e-спек** не додано в цьому циклі: його не можна прогнати локально (потрібна збірка клієнта), а непрогнаний тест у CI ризикує червоним; наскрізну перевірку робимо на test-деплої після `cpd` + прогін Start-флоу в лабораторії (26.11).

## 9. Зміна скоупу (26.11, рішення власника): аддон для всіх ролей із Gym

Було «лише member»; стало: **member, trainer, admin** (manager лишається без аддона, бо в нього немає Gym). Що змінено: `manifest.roles`, гейти `trainLikeAProAvailable`/`useTrainLikeAProOn` (роль не зашита, перевірка `isAddonEnabled`/`isAddonAllowed`), `CatalogPromoRow`, сервер `setProgramStatus` (для id `tl-` тренер/адмін отримує ту ж транзакцію: власне призначення, архівація інших власних active; архівація запущеної `tl-` програми знімає призначення). Тренерська гілка захисту (`planActivation`) не змінена: у тренера/адміна немає чужого призначення. Тести: гейт (3 ролі + manager + без аддона), `setProgramStatus.tx` (+3), `CatalogPromoRow`; лабораторні кадри admin/trainer: список і Programs з рядком входу.
