## Дані й безпека

- Нове поле `inputMode` (`'wheel' | 'stepper'`) у `users/{uid}/meta/prefs`, звичайне поле як `theme`/`locale` (прецедент: `themeSync.ts`, `weekStart.ts`). Не зашифроване: це налаштування UI, не введення користувача про здоров'я. Рішення «відкрите поле» — зафіксувати в описі PR.
- Читання/запис — через існуючий слухач prefs у `store.ts`; новий `inputModeSync.ts` (чиста функція, без Firebase) за шаблоном `themeSync`. Локальний кеш — ключ у `localKeys.registry` (guard-тест `localKeys.guard.test.ts` вимагає запису).
- `firestore.rules`: prefs-документ уже дозволяє власнику merge-запис; перевірити, що не потрібна білий список полів (`npm run test:rules`).
- Дефолт для нових користувачів: **wheel** (рішення власника — нове за замовчуванням? **питання власнику**, див. нижче). Існуючі користувачі без поля — лишаються на −/+ до явного вибору, щоб не змінити звичну поведінку мовчки.

## Ризики

- iOS: haptic лише через `input[switch]`-хак, Vibration API недоступний — у MVP без haptic (за спайком). Нативний `select` на iOS дає рідне колесо.
- Довгі діапазони (вага до 500 кг крок 0,5 = 1000 рядків): віртуалізація вікном — **поза MVP**, ліміт діапазону навколо поточного значення; ручне введення покриває решту. Названо як відома межа.
- Доступність: `role=spinbutton`, aria-valuetext, клавіатура, `prefers-reduced-motion` — у T4.
- Бандл: нових залежностей немає.
