# План MVP — My Fit (трекер тренувань)

Дуже простий принцип: **MVP = я щодня реально логую тренування, і дані ніде не губляться.**
Нічого більше.

## Що вже готово ✅

Кодова база фактично покриває MVP цілком:

- **Сервер** (Node + Express + SQLite): авторизація одним акаунтом (JWT),
  CRUD тренувань і вправ, зали + візити, все через ідемпотентні upsert'и.
- **Клієнт** (React PWA): офлайн-черга в localStorage, оптимістичний UI,
  синк «сервер — єдине джерело правди», встановлення на головний екран телефона.
- **Трей-додаток** (Electron): сервер + швидке вікно біля годинника.
- **Установка завершена**: залежності стоять, нативні модулі зібрані,
  server/client/desktop зібрані, збірка client вирівняна з сирцями
  (перейменування → My Fit).

## Кроки до MVP (по порядку)

### 1. Перший запуск на Маку — 10 хв

```bash
cd gym-tracker
npm run tray        # 🏋️ в треї → відкрити вікно
```

Створити акаунт (після першого реєстрація закривається).

### 2. Перевірка, що нічого не зламано — 10 хв

```bash
npm run typecheck
GYM_DATA_DIR=$(mktemp -d) PORT=4499 npm run start -w server &
BASE=http://localhost:4499 node scripts/smoke.mjs   # тільки проти тестової БД!
```

Очікування: всі `ok`, нуль `FAIL`.

### 3. Телефон у домашній мережі — 15 хв

Відкрити `http://<IP-Мака>:4477` з телефона → «Додати на головний екран».
Залогуватись, увімкнути авіарежим, додати підхід → вимкнути → перевірити,
що черга синкнулась. Це головний тест офлайн-режиму.

### 4. Тиждень реального використання — головний крок

Просто логувати кожне тренування. Записувати тертя (зайві кліки, незручні
поля) у нотатки — це і є беклог після MVP. Критерій успіху: **7 днів
поспіль жодного тренування повз трекер**.

### 5. (Опційно, вже після MVP) Доступ з-за меж дому

Cloudflare Tunnel за `cloudflare/SETUP.md` — потрібен свій домен (~$10/рік).
Для MVP не потрібно: в залі вистачає офлайн-черги, синк відбудеться вдома.

## Свідомо ПОЗА MVP ❌

- 🥗 Харчування та 🤖 AI-оцінка тіла (плитки «Скоро» вже в меню — достатньо).
- Push-нотифікації та фонова геолокація (браузер не дає — чесно описано в README).
- Кілька користувачів, розшарювання, експорт.
- Cloudflare/домен (крок 5, після тижня використання).
- Будь-який редизайн: поки логування працює — UI не чіпаємо.

## Дані та бекап

`~/.gym-tracker/` (SQLite + JWT-секрет). Бекап = копія папки. Раз на
тиждень — досить для MVP.

## Примітка про перевірку (крок 2)

Хмарне середовище Claude не змогло прогнати smoke-тест: реєстр npm там
блокує частину пакетів (esbuild-бінарники, workbox тощо), тому залежності
в хмарі не ставляться. На Маку все стоїть — тест запускається локально
однією командою вище.
