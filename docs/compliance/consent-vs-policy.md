# Згода чи повідомлення? Правила версій Privacy Policy і Terms (SPO-452 / SPO-453)

Це інженерний довідник, не юридична консультація. Юридичні висновки нижче — гіпотези до перевірки юристом (SPO-258); невідоме позначено `{{ЮРИСТ}}`.

## 2. Чекліст «чи потрібне нове підтвердження?» (для кожної нової фічі)

Іди зверху вниз, зупиняйся на першому «так».

1. Нова категорія **особливих даних** (здоров'я, цикл, вага як здоров'я, біометрія) або нова **мета**, якої немає в розділі 3 Policy? → окрема згода (`categoryRegistry.ts`, новий kind) **і** `material` у `changelog.ts`.
2. Новий **одержувач / процесор** поза описаними категоріями (розділ «Who receives your data»)? → `material` (bullet `recipient`/`transfer`), запис у `docs/compliance/processors.md`.
3. Новий **строк зберігання** або зміна на довший? → `material` (`retention`).
4. Нова категорія **звичайних даних** в межах існуючої мети (напр., ще одне поле налаштувань) і підстава та сама (договір)? → `editorial`: рядок у таблиці розділу 3, нова версія, закривана примітка; повторного прийняття немає.
5. Лише формулювання / виправлення? → `editorial`.
6. Зміна лише в UI без зміни обробки? → версію не чіпаємо.

Згода (перемикач) потрібна, коли вона **сама є підставою** (Art. 6(1)(a), 9(2)(a)); для підстави «договір» або «законний інтерес» достатньо рядка в Policy й повідомлення.

## 3. Показ за встановленим (SPO-571 P5, рішення власника 11.11.2026)

- Сторінки Policy/Terms, відкриті з застосунку, показують лише те, що стосується встановлених аддонів (`legal/docScope.ts`: правила «розділ / рядок таблиці / пункт списку → аддони-власники», видно, якщо доступний хоч один). Лінза звужує лише обробку, що ПРИПИНЯЄТЬСЯ разом з аддоном (Atlas AI-чат, шаринг доступності: згоди відкликаються). Усе, що аддон зберігає і що лишається в акаунті після видалення (плани, історія чату, дані здоров'я, їхні строки й згоди), показується завжди (Art. 13). Лінза діє лише для авторизованого користувача; відвідувач бачить повний текст.
- Це лінза на ОДИН повний текст, а не другий документ: версія, `docPlainText`-хеш прийняття, гейт і публічна сторінка завжди беруть повний текст; поруч є перемикач «Показати повний текст». Номери розділів лишаються як у повному тексті (текст посилається на «section 14»).
- Нова згода/аддон з власним рядком у Policy = нове правило в `DOC_SCOPE` (тест перевіряє, що правило вказує на існуючий рядок у всіх мовах і що власники реальні).
- Гіпотеза для юриста `{{ЮРИСТ}}`: чи достатньо повного тексту як предмета прийняття, коли людині за замовчуванням показано звужений вигляд з явним перемикачем.

## 4. Рівень рішення: що змінюється для існуючих клієнтів

Міграція не потрібна: версії й записи не змінені, нічого не просимо підписати знову. Додане лише неблокуюче показування.

## 5. Питання юристу (список для SPO-258)

1. Чи достатньо «повного тексту як предмета прийняття + звуженого за замовчуванням вигляду» (розділ 3)?
2. Чи вважати автовідкликання згоди при видаленні аддона зміною обробки, що потребує повідомлення? Інженерна позиція: ні, воно лише зменшує обробку.
3. Для яких нових фіч підстава «договір» витримає без окремої згоди (граничні випадки: Planner availability для тренера лишаємо на згоді).
