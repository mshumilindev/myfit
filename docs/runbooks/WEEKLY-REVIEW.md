# Щотижневий огляд процесу (SPO-649)

Раз на тиждень (або коли власник попросить), 20 хв. Мета: знайти топ-3 вузькі місця, перевірити гіпотезу «до/після», завести дії в Triage. Без персональних даних і без тексту чатів: лише категорії й час.

## 1. Зібрати дані

| Що                                                                   | Звідки                                                                                      |
| -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| Потік: lead/cycle time, блокери, heartbeat                           | `node scripts/wf-metrics.mjs` (журнал `wf`)                                                 |
| CI: час, перший зелений прогін, флак                                 | `gh api repos/mshumilindev/myfit/actions/runs` (REST), `node scripts/ci-stage-times.mjs`    |
| Якість: вердикти верифікаторів, повернення з Done, баги після релізу | коментарі задач, `verify.json`, Linear (статус Done → In Progress)                          |
| Тертя власника: нагадування «продовжуй», повторні зауваження         | лічильник за категоріями (без тексту) у `wf`-журналі; повторне зауваження → lint/тест/guard |
| Помилки в проді                                                      | Cloud Error Reporting / логи функцій (після SPO-648)                                        |
| Швидкість pre-push                                                   | лог pre-push, ціль ≤2 хв (`.claude/rules/speed-budgets.md`)                                 |

## 2. Знайти вузькі місця

Топ-3 за впливом на власника: де він чекає найдовше, що повертається, що ламається вдруге. Кожне — гіпотеза причини і вимірюваний ефект виправлення.

## 3. Рішення

Для кожного вузького місця — одна дія: правило, перевірка в коді (guard/lint/тест), зміна процесу чи інструмент. Правило без перевірки машиною — запасний варіант. Дію заводимо в Triage, **у межах ліміту задач Linear** (чекліст у наявній задачі, якщо ліміт).

## 4. До/після

Перед зміною — заміряти показник; після — через тиждень порівняти. Не покращило — відкотити або змінити гіпотезу; результат записати в `docs/RISK-REGISTER.md` чи коментар до задачі.

## 5. Звіт власнику (5–8 рядків)

Що виміряно, топ-3, що змінено, чого це коштувало, що чекає на нього (одним пакетом).
