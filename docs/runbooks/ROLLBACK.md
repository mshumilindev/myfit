# Відкат: що робити, коли щось пішло не так

Принцип: спершу зупинити шкоду, потім розібратись. Не пиши в прод-дані з акаунта користувача. Інцидент з даними — негайно до власника (GDPR ≤72 год, `legal-compliance.md`).

## Hosting (клієнт)

1. Попередня версія: Firebase Console → Hosting → Release history → Rollback на останній зелений реліз (`spotter-64c3b`, потім `myspotter.fit`).
2. Клієнти з PWA-кешем оновлюються самі (SW); перевір, що старий клієнт сумісний з даними й callable.
3. Лише після відкату — виправлення новим комітом (без force-push), повний `cpd`.

## Functions

1. Відкат лише зачеплених функцій: передеплой попереднього коміту пакетами ≤10 з паузою ≥60 с (див. `.claude/skills/cpd/SKILL.md`). Голий `--only functions` не запускати.
2. Після відкату: smoke публічних викликів і логи без `container failed to start`.

## Rules / індекси

1. `firestore.rules` / `storage.rules`: деплой попередньої версії файлу з git; потім `npm run test:rules` на емуляторі.
2. Індекси не видаляй, поки є запити, що від них залежать.

## Дані й міграції

Міграції мають бути версіоновані й ідемпотентні (інваріант 3). Відкат даних — лише зворотною міграцією з тестом; дані користувача не видаляти «для чистоти».

## Після відкату
