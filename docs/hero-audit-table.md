# Аудит hero / верхніх блоків екранів (SPO-96, SPO-110 AC3)

Статус: **значення нижче виведені з CSS (токени й каскад), а не виміряні в браузері.** На пристрої, де писався аудит, немає
браузера. Виміряти реальну геометрію: зібрати Storybook і запустити `npm run audit:hero -- --url <storybook> --widths 390,768,1024,1440,1920`
(перевіряє перекриття, вісь, вертикальні/горизонтальні відступи, збіг країв бару й контенту). Колонки "стан" треба
підтвердити цим скриптом.

(`redesign.css`, `verify-pinned-headers`, відступ під заголовком на телефоні) діють без змін.

## Виправлені розбіжності

1. **"Muscle groups worked" (`.muscles-worked`) — інсет.** `styles.css` задавав `.session-screen .muscles-worked
{ padding: 0 var(--gutter) }` (18px) після desktop-скидання до 0, тому на десктопі блок був зсунутий на 18px відносно hero-бокса,
   дати й карток (усі 0), а на телефоні в минулому тренуванні — 18px проти 20px у хедера, дати й тіла (`--s-20`).
   Тепер: телефон past = `--s-20`; десктоп = 0 (специфічність підібрана так, щоб не перебити `session-has-rail`).
2. Дубльовані локальні правила `.settings-view .hist-head`, `.hist-list .hist-head`, `.settings-sub`, `.hist-list-sub` видалені:
   геометрію й підзаголовок тепер дає `PageHead`.

## SPO-110 AC3 (узгодженість з аудитом)

Висновок цього аудиту для чатів: горизонтальний край = край контенту сторінки (0), вертикальні відступи беруться з `--s-*`;
нижній відступ чату має бути тим самим спільним нижнім відступом сторінки (`ChatShell`, не окремо в кожному чаті).
Цей прохід `ChatShell` не змінював; AC SPO-110 перевіряються окремо.
