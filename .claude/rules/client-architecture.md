# Архітектура клієнта

- **Дані:** `store.ts` — Firestore-native: живі `onSnapshot`, запис напряму в Firestore (offline persistence ставить у чергу й відтворює сама; ручної черги в localStorage немає). Мутація спершу патчить стан у пам'яті, знімок звіряє до канонічного. Без Redux/Zustand/TanStack Query. Не дублюй стан сервера в компонентах (`useEffect + useState` для завантаження — анти-патерн).
- **Привілейоване** — лише `callFn()` з `api.ts` (обгортка `httpsCallable`). Голий `fetch`/axios у компонентах — ні. Порти, URL, ключі — не хардкодити.
- **Кеш і швидкість:** дані кешуються, перевіряються лише дельти; завантаження не блокує роботу. Кожен екран із даними має стани loading / empty / error / offline; офлайн — це статус синку, не червоний банер. Помилки не ковтаються (порожній `catch {}` заборонений).
- **Бізнес-логіка** (розрахунки, правила, моделі) — у чистих функціях без React/DOM, з юніт-тестами. Презентаційні компоненти кіту не знають про Firestore/шифрування/роутинг — дані й колбеки через пропси.
- **Стек зафіксований:** TypeScript strict (без `any`/`@ts-ignore` без коментаря й задачі), React 19 (лише функційні компоненти й хуки), Vite + `vite-plugin-pwa`, звичайний CSS (токени, `glass.css` — тема, `redesign.css` — layout-оверрайди, Tailwind/CSS-in-JS немає), ESLint + Prettier. Відхилення — ADR у `docs/adr/NNN-<тема>.md` у тому ж коміті.
- **Нейминг:** компоненти `PascalCase`, хуки `use*`, екрани `*View.tsx`/`*Page.tsx`; без `I`-префіксів і експортів на ім'я `Data`/`Item`/`Response`. Коментарі пояснюють «чому».
- **Продуктивність:** мемоізація лише за вимірюванням, віртуалізація довгих списків, стабільні ключі, lazy-loading маршрутів, без важких обчислень у рендері. Зайвий ре-рендер, запит і залежність — це ціна, яку називаємо.
- **Рефакторинг великого екрана:** типи → дані → стор → список → модалки → чисті хелпери; малі дифи, без масових міграцій незачепленого коду.
