# Цілісність тестів

- Наявний тест = поведінковий контракт. Падіння після зміни коду — спершу гіпотеза «регресія в імплементації»: виправляй код.
- Перевірку міняють лише коли змінилась очікувана поведінка (рішення в `docs/MVP.md`/ADR/чаті). Тоді до правки скажи, яка поведінка змінилась і чому, з цитатою. Намір неоднозначний — СТОП, спитай; не обирай трактування, що робить набір зеленим.
- **Заборонено заради зеленого:** порожні/`ok(true)` асерти; прибирання перевірки коду статусу чи форми; `skip`/`only`; видалення чи перейменування тесту без перенесення його перевірок; нові моки, що ховають реальну поведінку; зниження порогів покриття; ховання логіки в `exclude`; підміна e2e «сторінка відкрилась»; `--no-verify`.
- **Patch-coverage (SPO-268):** змінені оператори `client/src` покриті тестами ≥ `patch.statements` з `coverage-thresholds.json` (pre-push і CI `Patch coverage`; ADR 007). Локально: `node scripts/patch-coverage.mjs --run --base origin/main`.
- **Pre-push кореневі тести (SPO-270):** лише зачеплені (`scripts/root-tests-related.mjs`, ADR 008); повний набір з порогами — CI. Зміна конфігів/залежностей → повний набір і локально.
- **Пороги не знижуються** (SPO-47): корінь `vitest.config.ts` — 90/70/90/90 (statements/branches/functions/lines), `client/vitest.config.ts` — 80. Міняти можна лише вгору (див. «Пороги покриття лише ростуть» нижче).
- Нова поведінка, виправлений баг, непокритий край — завжди з тестом. Баг: спершу тест, що падає (переконайся, що падає), потім фікс.
- Фікстури лише синтетичні; demo-дані не потрапляють у продукт (`kit-guard`).
- Новий AC без рядка в матриці `docs/FEATURES-AC.md` — незавершена робота.
- Запуск: клієнтські — `cd client && npx vitest run src/<шлях>` (кореневий конфіг бачить лише `tests/**`); rules — `npm run test:rules`; e2e — Playwright. Повні набори — у CI.

# Пороги покриття лише ростуть

- Підлога — `coverage-thresholds.json` (пороги, `include`, `exclude` обох vitest-конфігів + інформативна `client_full_baseline`). Гард `npm run coverage:guard` (pre-push і окремий джоб CI) падає, якщо поріг нижчий за підлогу, з `include` щось зникло, до `exclude` додано новий запис або сама підлога нижча за базу в git.
- Піднімаєш поріг чи `include` у конфізі → у тому ж коміті `node scripts/check-coverage-thresholds.mjs --update` (запише підлогу лише якщо всі значення >= старих; `--baseline-from <coverage-summary.json>` піднімає й `client_full_baseline`).
- Нові `exclude` — лише із записом у Linear і рішенням власника; сам гард їх не пропустить, тож запис додається в підлогу окремим комітом з посиланням на задачу.
